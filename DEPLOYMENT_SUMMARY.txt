✅ 但项目可以通过两种方式部署到 Dokploy


【两种部署方案】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

┌─ 选项 A: Dockerfile + Dokploy UI（推荐 ⭐⭐⭐）
│
│ ✅ 优点：
│   • 通过 Dokploy UI 完全管理
│   • 自动处理卷和网络
│   • 一键部署和更新
│   • 不需要 SSH 访问
│   • 集成日志和监控
│   • 最简单的方式
│
│ 卷管理：
│   ✅ Dokploy 自动创建和挂载 Docker 命名卷
│   ✅ 无需手动配置
│   ✅ 卷位置: /var/lib/docker/volumes/workey-data/_data
│
├─ 选项 B: 直接运行 docker-compose（备选）
│
│ ✅ 优点：
│   • 完全自动化（CI/CD）
│   • 易于本地测试
│   • 编排多个服务
│
│ ❌ 缺点：
│   • 需要 SSH 访问服务器
│   • Dokploy UI 无法管理
│   • 需要手动配置反向代理
│   • 需要手动挂载卷
│
└─ 推荐选项 A！


【选项 A 快速配置（5 分钟）】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Step 1: 连接 GitHub
  → Dokploy UI → Create Application → Connect Repository
  → 选择你的仓库（workey）

Step 2: 配置构建
  → Build Type: Dockerfile
  → Dockerfile Path: Dockerfile
  → Docker Context: .

Step 3: 设置环境变量
  WORKEY_DATA=/app/data

Step 4: 配置卷挂载（重要！）
  Mount Path: /app/data
  Volume Type: Named Volume
  
  （可选但推荐）上传文件卷：
  Mount Path: /app/data/uploads
  Volume Type: Named Volume

Step 5: 配置端口
  Port: 8000

Step 6: 部署
  点击 "Deploy" 按钮

✅ 完成！应用将在你的域名上运行


【卷挂载说明】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

为什么需要卷？
  • SQLite 数据库需要持久化存储
  • 上传的文件需要持久化存储
  • 容器重启后数据必须保留

命名卷 vs 绑定挂载：
  ✅ 推荐: Named Volume (Docker 管理)
  ❌ 不推荐: Bind Mount (主机目录)

在 Dokploy UI 中：
  1. 应用详情 → Settings → Volumes
  2. 点击 "Add Volume"
  3. 输入 Mount Path: /app/data
  4. Volume Type: Named Volume
  5. 点击 "Create"

Dokploy 会自动：
  ✓ 创建 Docker 命名卷
  ✓ 挂载到容器的 /app/data
  ✓ 容器重启时保留数据
  ✓ 应用更新时保留数据

【Dockerfile 多阶段构建流程】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Stage 1: Frontend Build
  ├─ Node.js 18 Alpine
  ├─ 安装依赖（pnpm）
  ├─ 构建 React 应用
  └─ 输出: dist/

Stage 2: Backend Build
  ├─ Go 1.21 Alpine
  ├─ 下载模块
  ├─ 编译 Go 二进制
  └─ 输出: workey 可执行文件

Stage 3: Runtime
  ├─ Alpine 3.19 (最小镜像)
  ├─ 复制前端文件
  ├─ 复制后端二进制
  ├─ 设置卷: /app/data
  └─ 暴露端口: 8000

结果：优化镜像，仅 ~50MB

【常见问题解决】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

问题：数据库文件丢失
解决：检查卷是否正确挂载
  → Dokploy UI: Settings → Volumes 确认
  → 或 docker volume ls | grep workey

问题：上传文件丢失
解决：确保卷挂载了 /app/data
  → 检查 Mount Path 是否正确
  → 确保卷类型是 Named Volume

问题：容器无法启动
解决：查看日志找错误
  → Dokploy UI: Applications → Logs
  → 或 docker logs workey -f

问题：构建失败
解决：检查依赖
  → 检查 Node.js 版本（18）
  → 检查 Go 版本（1.21）
  → 查看构建日志

【常用命令】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  docker volume ls | grep workey

【关键理解】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. Dokploy 是什么？
   一个开源、自托管的部署平台（类似 Vercel/Heroku）

2. docker-compose vs Dockerfile Build Type？
   docker-compose：本地开发、多服务编排
   Dockerfile Build Type：Dokploy UI 完全管理（推荐）

3. 卷的作用？
   保证容器删除后数据不丢失
   支持数据在容器重启时持久化

4. 为什么多阶段构建？
   减小镜像大小（50MB vs 500MB+）
   提高部署速度

5. Dokploy 如何处理卷？
   自动创建 Docker 命名卷
   自动挂载到指定路径
   自动管理和备份
